# Linux 0.11 소스 분석 강의계획

## 수업 개요

- **분석 대상:** Linux 0.11
- **일정:** 2026년 9월 15일 ~ 12월 15일, 매주 화요일, 총 14회
- **종료 기한:** 2026년 12월 20일 이전 완료
- **운영:** 과제·제출물·수강생 발표 없이 수업 시간 안에서 학습
- **회당 시간:** 2시간 기준의 제안안이며, 시작 시각은 미정
- **선수 지식:** C의 포인터·구조체·함수 호출과 운영체제 기본 개념을 안다고 가정

휴강 없이 매주 진행하는 일정이다. x86 어셈블리와 하드웨어 개념은 소스 분석에 필요한 범위에서 수업 중 설명한다.

## 학습 목표

1. 부팅에서 첫 사용자 프로세스 실행까지의 흐름을 설명한다.
2. 시스템 콜, 인터럽트, 스케줄링이 어떻게 연결되는지 이해한다.
3. 프로세스 생성·실행·종료와 메모리 관리의 관계를 소스로 확인한다.
4. 파일 및 터미널 입출력이 커널 내부를 통과하는 경로를 따라간다.
5. 운영체제의 일반적인 원리와 Linux 0.11 특유의 구현을 구분한다.

## 버전 선정과 분석 범위

Linux 0.11을 주교재로 고정한다. 제한된 수업 시간 안에서 부팅·프로세스·메모리·파일 시스템을 연결해 읽는 데 초점을 둔다. 현대 커널과의 비교는 각 주제의 정리 및 마지막 수업에서 다룬다.

당시 x86의 세그먼트와 태스크 전환 방식 등을 현대 Linux의 구현과 동일하게 설명하지 않는다. 현대 커널의 VMA, SLUB, SMP 동기화, 최신 스케줄러는 본 과정의 상세 분석 범위에서 제외한다.

## 회당 운영 방식

| 시간 | 진행 |
|---|---|
| 15분 | 이전 수업의 호출 흐름과 핵심 개념 함께 복습 |
| 25분 | 이번 수업의 질문, 배경 개념, 핵심 자료구조 설명 |
| 60분 | 소스를 함께 읽으며 주요 호출 경로와 상태 변화 추적 |
| 20분 | 강사 실행 시연 또는 코드 흐름 재확인, 질문과 정리 |

매 수업은 질문 하나에서 출발한다. 예를 들어 “`fork()` 이후 부모와 자식은 어디에서 다시 실행되는가?”를 정하고, 진입점에서 주요 함수와 자료구조를 따라간다. 모든 분기와 장치별 세부 구현을 읽기보다 핵심 경로를 연결하는 데 시간을 쓴다.

과제, 사전 읽기, 제출물, 수강생 발표는 요구하지 않는다. 복습과 이해 확인은 수업 중 질의응답과 흐름도 정리로 진행한다. 진도가 늦어지면 세부 구현 분석을 줄여 핵심 흐름과 마지막 종합 복습 시간을 확보한다.

## 강사 준비 사항

- Linux 0.11 원본 소스를 기준으로 분석 자료를 준비한다.
- 실행에 수정본을 사용할 경우 원본과의 차이 및 수정 목적을 기록한다.
- 에뮬레이터와 부팅 이미지를 미리 준비하고 실행을 검증한다. 환경 구축 자체로 첫 수업 시간을 소모하지 않도록 한다.
- 디버거를 사용할 경우 소스와 실행 바이너리가 일치하는지 확인한다.
- 각 수업의 핵심 질문, 읽을 소스 범위, 호출 흐름도, 시연 지점을 준비한다.
- 실행 시연이 어려운 경우를 대비해 로그와 주요 화면을 준비한다.

### 로컬 소스와 분석 도구

- [`src/`](src/): Kernel.org에서 받은 Linux 0.11 원본 소스. 아카이브의 최상위 디렉터리를 제거하고 배치했다.
- [`downloads/`](downloads/): 원본 압축 파일, 공식 체크섬 목록, 다운로드 기록. SHA-256 일치와 추출한 100개 파일의 내용 일치를 확인했다.
- 빌드는 Docker의 x86 Linux 환경, 실행은 각 운영체제의 QEMU를 사용한다. Windows(WSL2)·Ubuntu·하모니카 Linux·macOS의 설치, 실행, 재빌드 방법은 [운영체제별 실행 안내](RUNNING.md)를 참고한다.

소스 읽기는 **VS Code + Microsoft C/C++ 확장**, 실행은 **QEMU**를 사용한다. 실행 디버깅은 QEMU의 GDB 연결 기능으로 확장할 수 있다. Bochs는 선택적인 비교 도구다.

| 도구 | 활용 | 참고 사항 |
|---|---|---|
| VS Code + C/C++ 확장 | 정의·참조 탐색, 파일 비교, 수업 중 코드 읽기 | 오래된 문법과 어셈블리 때문에 자동 분석 결과가 불완전할 수 있다. 전체 텍스트 검색을 병행한다. |
| Bochs 내부 디버거 | 부팅 명령어 실행, 레지스터·GDT·IDT·페이지 테이블 관찰 | 디버거를 지원하는 빌드와 Linux 0.11용 부팅·루트 디스크 이미지 준비가 필요하다. |
| QEMU + GDB | 중단점과 실행 상태 확인, 소스 수준 디버깅 환경 확장 | Linux 0.11에 맞는 실행 이미지와 일치하는 심볼 준비가 필요하다. 현대 커널용 실행 명령을 그대로 적용하지 않는다. |

처음에는 프로젝트 폴더를 VS Code에서 열고 `src/init/main.c`를 시작점으로 `src/kernel/sched.c`, `src/kernel/fork.c`, `src/mm/memory.c`를 살펴본다. 부팅 자체의 시작점은 `src/boot/bootsect.s`이다.
