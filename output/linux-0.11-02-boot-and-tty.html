5

main() 이전의 실행

CPU 리셋 후 펌웨어 코드가 먼저 실행된다.

이 실습에서는 BIOS가 부트 섹터를 0x7C00에 읽는다.

bootsect.s가 setup과 커널 본체를 메모리에 적재한다.

setup.s와 head.s가 C 코드 실행에 필요한 상태를 만든다.

커널의 main()은 부팅 전체의 첫 명령이 아니다.

Linux 0.11 소스 분석 · 2회차

6

bootsect.s의 적재 순서

0x7C00의 부트 섹터를 0x90000으로 복사하고 그곳으로 점프한다.

BIOS int 0x13으로 setup 4개 섹터를 0x90200에 읽는다.

커널 본체 system을 0x10000부터 읽는다.

적재를 마치면 setup의 시작점으로 점프한다.

코드를 메모리에 읽는 동작과 그 코드로 점프하는 동작은 별개다.

스택과 call · ret

push는 값을 스택에 저장하고 스택 포인터를 낮춘다.

pop은 스택에서 값을 꺼내고 스택 포인터를 높인다.

일반적인 근거리 call은 돌아올 주소를 저장하고 이동한다.

ret은 스택의 복귀 주소를 꺼내 실행을 이어간다.

pushl $_main

jmp setup_paging


/* setup_paging의 마지막 */

ret

사용자 모드 진입과 첫 fork()

초기화 중이던 task 0이 사용자 모드로 이동한다.

fork()는 시스템 콜로 커널에 들어가 자식을 만든다.

자식은 0을 반환받아 init()을 실행한다.

sti();

move_to_user_mode();

if (!fork()) {

init();

}

for (;;) pause();

소스 파일이 init/main.c에 있어도 init()의 실행 권한은 사용자 모드다.

Linux 0.11 소스 분석 · 2회차

초기 스크립트와 대화형 셸

init의 자식이 /etc/rc를 표준 입력으로 연다.

execve("/bin/sh", ...)로 초기 스크립트를 실행한다.

init은 해당 자식의 종료를 기다린다.

새 자식이 세션과 tty0을 준비하고 대화형 셸을 실행한다.

fork()는 프로세스를 만들고, execve()는 그 프로세스의 프로그램을 바꾼다.

보충 · TTY 큐와 대기·깨우기

큐저장하는 것주요 처리
read_q키 해석을 거친 입력copy_to_cooked()가 꺼낸다
secondary줄 편집 등 처리한 입력tty_read()가 꺼낸다

void chr_dev_init(void)

void tty_init(void)

{

rs_init();

con_init();

}
