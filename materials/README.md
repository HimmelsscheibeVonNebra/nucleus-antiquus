# 한국어 강의 자료 제작 계획

강사 실행 시연과 소스 해설 중심의 16회 과정이다. 수강생 환경 구축, 제출 과제는 요구하지 않는다. 기준 소스는 `src/`, 실행·수정 대상은 `lab/`이며 둘을 혼동하지 않는다.

## 모든 발표의 필수 구성

1. 전체 과정 지도와 이번 회차의 위치를 제시한다. 각 슬라이드에도 현재 설명 중인 단계의 작은 지도를 표시한다.
2. 상태 변화도를 포함한다. 상태 이름, 전환 원인, 변경되는 데이터, 그대로 유지되는 조건을 설명한다. 단순 호출 순서와 상태 변화는 구분한다.
3. 모드나 선택지가 등장하면 범위를 먼저 정하고 그 범위의 모든 선택지를 비교한다. 사용 여부, 전환 조건, 관련 소스도 표시한다. CPU 모드, 권한 수준, 태스크 상태, 정책을 같은 분류로 섞지 않는다.
4. 핵심 질문 → 배경 → 짧은 실제 코드 → 상태 변화 → 강사 시연 → 질문의 답 순서로 진행한다.
5. 실제 관찰 결과와 코드에서 추론한 결과를 구분한다. 실행 환경, 버전, 수정 사항, 검증 여부를 기록한다.

## 회차별 계획

| 회차 | 주제 | 상태 변화도 | 모드·선택지 비교 범위 | 제작 상태 |
|---|---|---|---|---|
| 01 | CPU·어셈블리 입문과 부팅부터 셸까지 | 명령 실행·스택·부팅·권한·fork·exec | 80386 모드, CPL 0~3, PG 0/1, IF 0/1, open 접근 모드 | 42장 입문 개정 |
| 02 | x86 소스 읽기 | 스택·레지스터, 게이트 진입 | 세그먼트 종류, 게이트 종류, 주소 분류 | 계획 |
| 03 | 부팅과 초기화 | PE·PG·IF·CPL의 단계별 변화 | 부팅 경로의 CPU 모드와 각 제어 비트 | 계획 |
| 04 | 인터럽트·예외·시스템 콜 | 진입·레지스터 저장·복귀 | interrupt/trap/task gate, 예외 분류, 하드웨어 IRQ | 계획 |
| 05 | 태스크와 스케줄링 | runnable/sleeping/stopped/zombie | 0.11의 TASK_* 전체, counter와 priority | 계획 |
| 06 | fork와 프로세스 생성 | 부모·자식 분기와 자원 공유 | fork의 음수/0/양수 반환, 복사/공유 자원 | 계획 |
| 07 | 주소 변환과 페이지 | 주소 변환과 페이지 할당·해제 | P/RW/US 비트, 논리/선형/물리 주소 | 계획 |
| 08 | 페이지 폴트와 COW | 공유 읽기 전용 → 쓰기 폴트 → 분리 | 80386 페이지 폴트 오류 코드의 P/W/U 조합 | 계획 |
| 09 | exec와 프로그램 실행 | 같은 PID의 주소 공간 교체 | 0.11 로더가 지원하는 실행 형식·오류 경로 | 계획 |
| 10 | 종료·대기·시그널 | 종료 → zombie → 회수 | waitpid 옵션, 시그널 기본/무시/핸들러와 예외 | 계획 |
| 11 | 파일 시스템과 버퍼 캐시 | 버퍼의 유효·dirty·잠금 변화 | 관련 버퍼 플래그 및 조합 | 계획 |
| 12 | 경로 탐색과 I/O | 경로 → inode → file → fd | 0.11 open 접근 모드와 지원 플래그 | 계획 |
| 13 | 터미널 I/O | 입력 큐·대기·깨우기 | 0.11 termios의 실제 지원 플래그, canonical 여부 | 계획 |
| 14 | 종합과 현대 커널 비교 | 셸 명령의 생성·실행·I/O·종료 | 앞선 분류를 통합, 현대 커널과의 차이 명시 | 계획 |
| 15 | 현대 Linux 커널 모듈 | 미적재 → 초기화 → 사용 → 제거 | built-in/module/off, 매개변수 권한과 수명 주기 | 계획 |
| 16 | 새 스케줄러: 0.11 / 현대 Linux | runnable → 선택 → 실행 → 재선택 | 0.11 기존/실험 정책, 고정 버전 sched_ext 전환 옵션 | 계획 |

표의 비교 범위는 제작 체크리스트다. 실제 플래그 목록은 각 회차에서 선택한 소스 버전으로 검증한다. “모든 모드”는 모든 CPU 세대나 모든 커널 버전을 뜻하지 않는다.

## 현대 커널 환경

15회차는 일반 `.ko` 모듈, 16회차 현대 커널 부분은 BPF 기반 `sched_ext`를 사용한다. 일반 모듈이 스케줄링 클래스를 자유롭게 추가할 수 있다고 설명하지 않는다. VM의 커널 릴리스·설정·헤더·컴파일러·BPF 도구·예제 커밋은 구현 전에 고정한다. 현재는 미선정이며 최신 버전이라고 가정하지 않는다. Secure Boot와 모듈 서명, sched_ext 지원 여부를 점검한다.

기존 14회 일정은 유지한다. 15~16회 날짜는 미정이다. 기존 종료 기한인 12월 20일 이전에 포함하려면 별도 일정 협의가 필요하다.

## 자료와 재생성

- `../output/01-overview.pptx`: 편집 가능한 한국어 발표 자료.
- `../output/01-overview.pdf`: 동일 슬라이드의 배포·검토용 PDF.
- `01-overview/demo.md`: 강사 시연 절차와 대체 자료.
- `01-overview/notes.md`: 슬라이드별 해설과 예상 질문.
- `../scripts/make_slides.py`: 표준 라이브러리와 LibreOffice UNO로 만드는 재현 가능한 생성기.

프로젝트 루트에서 실행한다. Debian/Ubuntu 기준 `libreoffice-impress`, `python3-uno`, `fonts-noto-cjk`가 필요하다. UNO를 제공하는 시스템 Python을 사용한다.

```bash
/usr/bin/python3 scripts/make_slides.py
/usr/bin/python3 scripts/check_slides.py
```

생성기는 임시 LibreOffice 프로필을 사용하고 원본 커널과 기존 OTP 템플릿은 수정하지 않는다. 기존 템플릿은 Python 강의용이므로 이번 초안은 커널 상태도와 코드 해설에 맞춘 별도 레이아웃을 사용한다. 결과물의 텍스트와 도형은 편집 가능하며, 글꼴은 포함하지 않으므로 다른 PC에도 Noto Sans CJK KR 설치를 권장한다.

검사기는 `poppler-utils`의 `pdfinfo`, `pdftotext`도 사용한다. PPTX/PDF의 42장 일치, 편집 가능한 도형, 슬라이드마다 있는 위치 지도, 필수 상태도·모드 설명과 PDF 텍스트 출력을 검사한다. CPU·어셈블리·프로세스 설명이 해당 원본 코드보다 먼저 등장하는지도 확인한다. 실행 시연 자체를 검증하는 검사는 아니다.

1회차는 CPU 구조·보호 모드·어셈블리 선수 지식이 없는 수강생 기준으로 개정했다. 120분 중 기초 설명을 우선하고, 코드의 세부 분석 일부는 강사용 참조로 활용한다. 시간 배분과 각 장의 풀이·확인 질문은 `01-overview/notes.md`에 있다.

2026-10-31 입문 개정 검증: 42장 PPTX/PDF 구조·내용·선수 개념 순서 검사 통과. LibreOffice 24.2에서 PPTX를 다시 열어 PDF 변환 및 42장 유지를 확인했다. 어셈블리 표기, GDT 설명, 제어 비트 참조표, fd 접근 모드 슬라이드를 이미지로 점검했다.

Microsoft PowerPoint에서의 직접 확인과 이번 작업 중 QEMU 부팅 재검증은 수행하지 않았다. 02~16회 PPTX는 아직 제작하지 않았다.
