# 슬라이드 공통 프레임 규격 — 15회차 전체 적용

작성일 2026-11-08. 이 문서는 `materials/course-plan.md`(15회차 전체 설계)를 회차별 상세 제작 계획
(`materials/slide-plans/NN-<slug>.md`)으로 확장할 때 **모든 회차가 공유하는 규격**이다.
개별 회차 계획은 아래 규격을 전제로 쓰며, 반복 기술하지 않는다.

요구 반영:

1. **모든 자료에 Linux 0.11 버전 표시** — 현대 커널 자료와의 혼동 방지 (§1).
2. **앞부분에 현재 순서 다이어그램** — 15회차 로드맵에서 오늘 회차 강조 (§2, 표준 앞부분 슬라이드 03).
3. **전체 구조 다이어그램** — Linux 0.11 커널 전체 구조도에서 오늘 범위 강조 (§2, 표준 앞부분 슬라이드 04).
4. **장수 증가 허용** — 기존 계획 대비 +4~8장 (§5).

## 1. Linux 0.11 버전 표시 규칙 (전 슬라이드 필수)

표기는 항상 `Linux 0.11` (공백 포함, 첫 글자만 대문자). "리눅스", "커널" 단독 표기는 버전 정보를
대신하지 못한다. 최초 등장 슬라이드(표지)에서 다음 사실을 한 번 명시한다: **1991년 12월 공개,
Kernel.org 원본 `src/` 기준, 실행은 `lab/` 수정본(QEMU i386)**.

| 위치 | 내용 | 형식 |
|---|---|---|
| 표지(슬라이드 01) 우상단 | `Linux 0.11` 배지 + `1991` | ORANGE 채움 · PAPER 글자 · 모서리 둥근 사각 |
| 표지 부제 한 줄 | `Kernel.org 원본 src/ 기준 · 실행은 lab/ (QEMU i386)` | MUTED 글자 |
| 모든 슬라이드 푸터 좌측 | `Linux 0.11 커널 강좌 · NN/15 · <회차 슬러그>` | MUTED, 작은 글씨 |
| 모든 슬라이드 푸터 우측 | `MM / 총 장수` 슬라이드 번호 | MUTED |
| 코드 슬라이드 캡션 | `src/<파일>:<시작줄>–<끝줄>` — 항상 원본 기준. `lab/` 캡처와 병치할 때는 "lab/ 수정본 (심볼 `_` 접두 등 차이)" 각주 | |
| 다이어그램(로드맵·구조도·상태도 공통) | 제목 또는 우하단 모서리에 `Linux 0.11` 라벨 | |

수강생에게 주는 의미(표지 발표 멘트용 한 줄): "이 강의의 모든 줄 번호와 동작은 1991년 Linux 0.11
기준이다. 현대 커널 이야기가 나올 때마다 '0.11에는 없다/다르다'고 명시한다."

## 2. 표준 앞부분 — 슬라이드 01–04 (모든 회차 동일 구조, 내용은 회차별)

기존 회차 계획의 "15회차 지도" 슬라이드는 아래 03·04 다이어그램 두 장으로 대체·확장한다.

### 슬라이드 01 표지 — 유형 `표지`

- 대제목: `NN. <회차 제목>` (course-plan 지도 표의 제목 그대로)
- 부제: 이 회차의 핵심 질문 원문 전체
- 배지·부제: §1 규칙
- 회차 정보: `NN/15 · 파트 <X> «<파트명>»`

### 슬라이드 02 핵심 질문과 오늘의 길 — 유형 `질문`

- 핵심 질문 1문장 큰 글씨 (원문 그대로)
- 오늘의 길: §3의 10단계 미니 지도를 본문 크기로 놓고 오늘 실제로 다루는 단계만 강조.
  회차에 없는 단계(예: 상태도가 없는 회차)는 "오늘은 다루지 않음"으로 회색 처리 — 무리하게 채우지 않는다.

### 슬라이드 03 과정 로드맵 — 오늘의 위치 — 유형 `로드맵` [다이어그램]

15회차를 7개 파트로 묶은 타임라인. **오늘 회차만 강조**해 "현재 순서"를 보여준다.

파트 구성 (로드맵의 기본 골격, 전 회차 동일):

| 파트 | 이름 | 회차 |
|---|---|---|
| A | 입문·부팅 | 01 CPU·어셈블리 · 02 보호 모드 · 03 부팅·초기화 |
| B | 실행의 길 | 04 인터럽트·시스템 콜 · 05 스케줄링 · 06 fork |
| C | 메모리 | 07 주소 변환 · 08 페이지 폴트·CoW |
| D | 프로그램의 일생 | 09 exec · 10 종료·시그널 |
| E | 파일·저장 | 11 버퍼 캐시·블록 · 12 파일 시스템 |
| F | 터미널 | 13 터미널 I/O |
| G | 종합·실습 | 14 종합·현대 비교 · 15 커널 수정 실습 |

목업 (실제 슬라이드는 도형으로 제작, 05회차 예시 — 각 회차 계획의 §3에 회차별 강조 위치·문구 명세):

```
 파트 A «입문·부팅»     파트 B «실행의 길»          파트 C «메모리»
 ┌───┬───┬───┐     ┌───┬───┬───┐      ┌───┬───┐
 │ 01│ 02│ 03│     │ 04│ 05│ 06│      │ 07│ 08│
 └───┴───┴───┘     └───┴───┴───┘      └───┴───┘
  ■   ■   ■          ■  ▶   □           □   □

 파트 D «프로그램의 일생»  파트 E «파일·저장»   파트 F      파트 G «종합·실습»
 ┌───┬───┐            ┌───┬───┐        ┌───┐      ┌───┬───┐
 │ 09│ 10│            │ 11│ 12│        │ 13│      │ 14│ 15│
 └───┴───┘            └───┴───┘        └───┘      └───┴───┘

 범례  ■ 완료(TEAL)   ▶ 오늘(ORANGE)   □ 이후(MUTED)   · Linux 0.11 커널 강좌
```

제작 규칙:

- 상태 3색: 완료 = TEAL 채움, 오늘 = ORANGE 채움 + 굵은 테두리, 이후 = MUTED 외곽선만.
- 오늘 상자 아래에 **오늘 한 줄 문구** (회차별 명세).
- 앞 회차 → 오늘, 오늘 → 다음 회차를 잇는 화살표 2개와 각각 **연결 문구 한 줄**
  (예: "04: `int 0x80` 진입을 봤다 → 05: 그 끝의 `ret_from_sys_call`에서 누가 이어서 실행되는가").
- 파트 A–G 라벨과 파트별 묶음 테두리. 우하단 범례 + `Linux 0.11` 라벨.
- 01회차는 완료 상자 없음(전부 □), 14·15회차는 01–13 완료 처리.

### 슬라이드 04 커널 전체 구조 — 오늘의 범위 — 유형 `구조` [다이어그램]

Linux 0.11 전체 구조도. **오늘 다루는 파일·계층만 강조**하고 나머지는 실루엣으로 남긴다
(가리지 않는다 — "전체에서 오늘의 위치"가 목적).

목업 (기본 골격, 전 회차 동일):

```
┌ 사용자 공간 (CPL=3) ───────────────────────────────────────────┐
│ init · sh · 응용 프로그램   (init/main.c 가 fork/exec 로 생성)   │
└──────────△ int 0x80 (번호: include/unistd.h) △ read()/write() ─┘
┌ 커널 공간 (CPL=0) ─────────────────────────────────────────────┐
│ 진입: kernel/system_call.s · sys_call_table (include/linux/sys.h)│
│ ┌ 프로세스 (kernel/) ┐ ┌ 메모리 (mm/) ┐ ┌ 파일 시스템 (fs/) ┐  │
│ │ sched.c fork.c     │ │ memory.c     │ │ namei.c inode.c   │  │
│ │ exit.c signal.c    │ │ page.s       │ │ buffer.c exec.c   │  │
│ └────────────────────┘ └──────────────┘ └───────────────────┘  │
│ ┌ 블록 장치 (blk_drv/) ┐ ┌ 문자 장치 (chr_drv/) ┐ ┌ 공통 ┐    │
│ │ ll_rw_blk.c hd.c    │ │ console.c tty_io.c   │ │main.c│    │
│ │ floppy.c ramdisk.c  │ │ keyboard.S serial.c  │ │printk│    │
│ └─────────────────────┘ └─────────────────────┘ └─────┘    │
└──────────▽ IRQ ▽─────────────────────────────────────────────┘
   8259A PIC · 8253 타이머(IRQ 0) · 키보드(IRQ 1) · 하드디스크(IRQ 14)
```

제작 규칙:

- 오늘 범위 = 해당 파일 상자 TEAL 채움 + 오늘의 **데이터 흐름 화살표 1–2개** ORANGE.
- 범위 밖 상자는 MUTED 외곽선, 라벨만 유지.
- 계층 경계(사용자/커널/하드웨어)는 굵은 구분선 + CPL·IRQ 라벨.
- 우하단 `Linux 0.11` 라벨. 이 다이어그램의 골격은 회차가 진행될수록 "채워진 영역"이 넓어진다
  (누적 강조 — 지난 회차 파일은 옅은 TEAL로 남기고 오늘 파일을 진하게).

## 3. 상단 미니 지도 (본문 전 슬라이드 공통)

모든 본문 슬라이드(05번부터) 상단에 10단계 띠. 현재 단계만 ORANGE 점 + 라벨, 나머지 MUTED.


| 표지 | 질문 | 슬라이드 01 |
| 질문 | 질문 | 핵심 질문 제시 |
| 로드맵 | 지도 | 슬라이드 03 |
| 구조 | 지도 | 슬라이드 04 |
| 배경 | 배경 | 개념·그림·CPU 동작 |
| 코드 | 코드 | 원본 코드 인용·해설 |
| 상태도 | 상태도 | 상태 변화도 |
| 비교 | 비교 | 모드·선택지 비교표 |
| 시연 | 시연 | 시연 절차 슬라이드 |

## 4. 표준 뒷부분

기존 course-plan 구성 유지: 이해 확인 문항(4문항, 정답 포함) → 정리·다음 회차 예고.
마지막 슬라이드 푸터에도 §1 표기가 들어가므로 별도 버전 슬라이드는 필요 없다.

## 5. 장수·시간 정책

- 기존 계획 대비 **+4~8장 확장 허용**, 목표 **44–50장**. 증가분 우선순위:
  1. 표준 앞부분 확장(지도 1장 → 로드맵+구조도 2장),
  2. 밀도 높은 기존 슬라이드의 분할(코드 2스크린 이상, 비교 축 3개 이상),
  3. 다이어그램 전용 슬라이드(코드+그림을 한 장에 억지로 넣지 않는다).
- 120분 운영안 표는 새 슬라이드 번호로 다시 쓰되 단계별 분배 비율은 원진 유지.
- 장수 변경 사유는 회차별 계획의 "기존 계획 대비 변경" 절에 남긴다.

## 6. 색·서체 (scripts/make_slides.py 팔레트와 동일)

| 값 | 색 | 용도 |
|---|---|---|
| NAVY `0x102532` | 진남색 | 슬라이드 배경 |
| INK `0x183340` | 남색 | 보조 배경·상자 |
| PAPER `0xF4F1E9` | 종이색 | 본문 글자 |
| TEAL `0x75D5C5` | 청록 | 완료·일반 강조·코드 배경 |
| ORANGE `0xFFB66B` | 주황 | **오늘·현재 위치** 강조 전용 |
| MUTED `0xABC0CB` | 회청 | 이후·약화·푸터·각주 |

서체 Noto Sans CJK KR. 원칙: 강조색 ORANGE는 "지금/오늘/현재"에만 쓴다(로드맵의 오늘 회차,
미니 지도의 현재 단계, 구조도의 오늘 흐름 화살표). 완료·일반 강조는 TEAL. 다이어그램은
편집 가능한 도형으로 만든다(이미지 붙이기 아님).

## 7. 캡처·출처 규칙 (기존 규칙 재인용 + 파일명 규칙)

- 실제 관찰(캡처)과 코드 추론을 슬라이드에서 구분. 캡처 각주 필수 항목:
  `lab/ 빌드 · QEMU i386 · GDB · 수정 없음/있음(내용) · 캡처 날짜`.
- 사전 캡처는 화면 모서리에 `기존 기록` 라벨. 사전 캡처 파일: `build/boot.png` 등 기존 자산 활용.
- 회차별 신규 캡처 보관: `materials/<NN-슬러그>/captures/<두자리순번>-<설명>.png`
  (예: `materials/05-scheduling/captures/10-tick-jiffies-counter.png`).
- 시연 뒤 "관찰 vs 추론" 구분 슬라이드 1장 유지(기존 규칙).
