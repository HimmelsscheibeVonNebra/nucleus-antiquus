## 1. 회차 개요

- **핵심 질문**: 셸이 나오기 전에 누가 실행되는가?
- **학습 목표** (원천 계승):
  1. CPU는 C 문장이 아니라 기계어를 실행하며, 명령 하나가 레지스터·메모리·플래그 중 무엇을 바꾸는지 말할 수 있다.
  2. as86(목적지, 원본)과 AT&T(원본, 목적지) 두 어셈블리 문법의 피연산자 순서 차이를 구분한다.
  3. 실주소 모드와 보호 모드, CPL 0/3, PE/PG/IF가 서로 다른 축임을 안다.
  4. BIOS → bootsect → setup → head → main() → task 0/init → 셸의 전체 경로를 학습자의 말로 요약한다.
  5. 프로그램·프로세스·PID·fd의 일상어 정의와 fork/exec/wait의 역할을 말한다.
- **읽을 소스 범위** (원본 src 기준):

- **상태 변화도 / 비교 범위** (새 슬라이드 번호로 계승):
  - 상태 변화도(31장): 단계별 PE/PG/CPL/IF — BIOS(0/0/—/1) → setup `cli`(IF=0) → `lmsw`(PE=1) → head `setup_paging`(PG=1) → main `sti`(IF=1) → `move_to_user_mode`(CPL=3). 전환 원인은 각 명령, 변경 데이터는 CR0·EFLAGS·CS 선택자. "IF는 표시 지점의 값"이라는 주의 유지.
  - 모드 비교(32장): 80386 CPU 모드 = real-address / protected / virtual-8086 — 세 가지 전부. 0.11 경로는 real→protected, VM86 미사용.
  - 권한 비교(33장): CPL 0/1/2/3 전부. 0.11 주 경로는 0과 3.
  - 제어 비트 비교(34장): PG 0/1, IF 0/1.
  - open 접근 모드 비교(40장): O_RDONLY/O_WRONLY/O_RDWR.
- **시연 원칙**: GDB는 이번 회차에서 사용하지 않는다(02회차부터). demo.md의 시연 A/B/C 전체를 추가하면 120분 초과이므로 실제 강의는 축약안(시연 A 약 7분 + 셸 연결 약 3분), 시연 B(소스 연결)는 본문 코드 슬라이드 28–30·35–36·38–39·41–42에서 대체 수행.

### 슬라이드 03 로드맵 — 오늘 위치

- 파트 골격: 00-common §2의 7파트(A–G) 타임라인 그대로. 오늘은 **파트 A «입문·부팅»의 첫 회차**.
- 완료 회차: **없음** — 첫 회차 규칙(완료 상자 없음, 전부 □). 오늘 01 = ORANGE 채움 + 굵은 테두리. 이후 회차: 02–15 전부 MUTED 외곽선만.
- 오늘 한 줄 문구(01 상자 아래): "셸이 나오기 전에 누가 실행되는가 — BIOS부터 셸까지 전체 경로를 한 번에 통과하는 첫 회차".
- 연결 화살표: 앞 회차→오늘 화살표는 **없음**(첫 회차). 오늘→다음(01→02) 화살표 문구: "01: 부팅 전체 경로와 PE·PG·CPL·iret 프레임을 처음 만났다 → 02: 선택자 하나가 어떻게 주소가 되는가 — 보호 모드를 GDB로 확대한다".
- 우하단 범례(■ 완료 · ▶ 오늘 · □ 이후) + `Linux 0.11` 라벨. 기존 42장의 "지도" 슬라이드(16회차 표기)는 이 다이어그램으로 대체·흡수되며 15회차판으로 갱신된다.

### 슬라이드 04 커널 구조도 — 오늘 범위

- 하이라이트 파일·계층(TEAL 채움): **boot/bootsect.s, boot/setup.s, boot/head.s** — 구조도 골격에 boot/ 계층 행(부트 섹터 → setup → head)을 라벨과 함께 추가. **init/main.c** — 골격의 「공통(main.c·printk)」 상자. **lib/** — 골격에 커널 라이브러리 계층 상자를 라벨만 추가. 사용자 공간의 init·sh 라벨(오늘 경로의 도착점)도 강조.
- 오늘의 데이터 흐름 화살표(ORANGE, 출발→경유→도착): 부트 섹터(boot/bootsect.s) → setup(boot/setup.s) → head.s(boot/head.s) → main(init/main.c) → 셸(사용자 공간, init이 fork/exec한 /bin/sh).
- 누적 강조할 지난 회차 영역: **없음**(첫 회차 — 진한 강조는 오늘 파일뿐, 누적 규칙은 02회차부터 적용).

## 6. 이해 확인 질문과 정답 (해당 슬라이드 번호 명시)

문항 슬라이드 **46**, 정답 슬라이드 **47**. 원천(course-plan `# 01` 절) 전문 계승:

1. CPU가 직접 실행하는 것은? — 기계어(C 문자열이 아님).
2. `[0x1000]`의 값을 12로 바꾸면 주소도 바뀌는가? — 아니오. 주소와 값은 별개.
3. as86 `mov ax,#1`과 AT&T `movl $1,%eax`의 차이는? — 피연산자 순서가 반대(목적지,원본 / 원본,목적지).
4. 사용자 프로그램은 어느 CPU 모드에서 실행되는가? — 보호 모드(CPL 3). real mode가 아님.
5. 첫 fork의 부모(task 0)는 무엇을 하는가? — `for(;;) pause();` 루프 (main.c:148).
6. 셸은 누가 실행하는가? — init이 fork한 자식에서 execve("/bin/sh") (main.c:194-200).
7. exec 뒤 PID는? — 그대로 유지, 주소 공간과 실행 이미지만 교체.
8. 셸이 종료되면 누가 회수하는가? — init의 `wait` 루프 (main.c:202-206), 그 뒤 새 셸을 다시 fork.

강의 중 확인 질문은 본문에 배치: 슬라이드 07("[0x1000]을 12로 바꾸면 주소도 12가 되는가?"), 슬라이드 29(3줄 각각의 변경 상태 묻기), 슬라이드 13(push/pop 뒤 ESP와 스택 값 질문 — demo.md 축약안).

## 8. 흔한 오해 / 말하지 말아야 할 것

- 실주소 모드를 "제한이 없는 모드"라고 부르지 않는다.
- "인터럽트는 모두 장치에서 온다"고 말하지 않는다(int 0x80 시스템 콜).
- iret가 범용 레지스터를 자동 복구한다고 말하지 않는다.
- 상태도의 레지스터 값 예시는 설명용이며 실측이 아님을 명시한다.
- move_to_user_mode는 새 프로세스 생성이 아니라 같은 task의 권한 변경이다.
- 첫 fork는 성공을 가정한다(main.c:138 주석 "we count on this going ok").
- 현대 x86-64 long mode, UEFI, SMM은 범위 밖. 현대 호스트 커널과 0.11을 혼동하지 않게 한다.
- 캡처는 lab/(수정본)에서 얻은 것이며 슬라이드 인용 줄 번호는 src/ 원본 기준임을 각주로 분리한다.
