# 01 강사 시연: 부팅 결과에서 소스로

## 초보자용 진행 순서

강사는 먼저 슬라이드 03~18에서 CPU·RAM·레지스터·어셈블리·보호의 필요를 설명한다. 수강생에게 레지스터 이름을 미리 알고 있다고 가정하지 않는다. 기존 30분 시연을 약 10분으로 줄이고 아래 순서로 수행한다. 상세 소스 추적은 설명 시간에 나눠 진행한다.

1. 슬라이드 10의 `movl $1,%eax`와 `addl $2,%eax`를 가리키며 EAX가 미정→1→3으로 바뀌는 것을 추적한다. 이는 설명용 예시이며 실행 측정은 아니다.
2. 슬라이드 11의 push/pop 후 ESP와 스택 값이 어떻게 달라지는지 질문한다.
3. 슬라이드 22에서 QEMU 부팅과 echo/ls를 약 7분간 보여준다.
4. 슬라이드 25~26에서 원본 3줄을 열고 “준비→PE 설정→실행 위치 변경”으로 읽는다.
5. 슬라이드 40에서 셸 결과와 전체 지도를 약 3분간 연결한다.

아래 시연 A/B/C의 시간은 전체 절차를 별도로 연습할 때의 분량이다. 모두를 수업에 추가하면 120분을 초과하므로 실제 강의는 위 축약안을 사용한다.

## 준비와 검증 범위

- 프로젝트 루트에서 진행한다. 읽기 기준은 `src/`, 부팅 바이너리와 수정본은 `lab/`이다.
- `RUNNING.md`와 `build/UPSTREAM.md`, `build/source-changes.patch`로 환경 및 수정 내역을 확인한다.
- 이 자료는 새로운 부팅 성공을 보증하는 로그가 아니다. `build/boot.png`는 기존 검증 화면이며 이번 시연의 실시간 결과로 소개하지 않는다.
- `lab/Image`와 `lab/hdc-0.11.img`, QEMU GUI 환경을 수업 전에 확인한다.

## 시연 A: 셸까지 도달하기 (10분)

호스트 터미널:

```bash
qemu-system-i386 --version
bash scripts/run.sh
```

`run.sh`는 TCG, 16 MiB RAM, 플로피 부팅, IDE 루트 디스크, 네트워크 없음, `-snapshot`을 사용한다. 디스크 변경은 기본 이미지에 영구 반영하지 않는다. QEMU 창 안의 게스트 셸에서 입력한다:

```sh
echo boot-ok
ls /
```

관찰: 명령이 반환되고 루트 디렉터리 목록이 나타나면 셸이 동작한다. 셸 화면만으로 PE·PG·CPL 값이나 모든 장치의 정상 동작을 검증했다고 말하지 않는다. 화면 및 출력 문자열은 루트 이미지에 따라 다르다. 게스트 셸의 `exit`은 init이 셸을 다시 생성할 수 있으므로 QEMU 종료와 같지 않다. 시연 종료는 QEMU 창 닫기로 한다.

## 시연 B: 결과를 코드와 연결하기 (15분)

1. `src/boot/bootsect.s`: 부트 섹터가 setup과 system을 읽는 큰 흐름을 찾는다.
2. `src/boot/setup.s:186-193`: `lmsw`의 PE 설정과 far jump를 설명한다.
3. `src/boot/head.s:198-218`: 초기 매핑, CR3 설정, CR0.PG 설정을 찾는다. 전체 물리 메모리가 16 MiB라는 일반 규칙으로 확대하지 않는다.
4. `src/init/main.c:126-148`: 초기화, `sti()`, 사용자 권한 전환, 첫 `fork()`를 읽는다.
5. `src/include/asm/system.h:1-14`: `iret` 프레임을 통한 CPL 3 전환을 보여준다. 보호 모드 자체는 유지된다.
6. `src/init/main.c:168-207`: setup, tty fd 구성, `/etc/rc`, 대화형 셸 생성과 wait 루프를 연결한다.

## 시연 C: 질문과 예측 (5분)

- 첫 fork의 부모는 어디로 가는가? task 0의 `pause()` 루프.
- 첫 자식이 바로 exec하는가? 아니다. 먼저 `init()`을 수행하고 추가 자식을 만들어 셸을 exec한다.
- exec 뒤 PID가 새로 생기는가? 아니다. 성공한 exec는 호출한 프로세스의 프로그램 이미지를 교체한다.
- 셸 종료 후에는? init이 해당 자식을 회수하고 다시 셸을 생성한다.

## 실패 시 대체 경로

QEMU나 GUI가 없으면 실행 성공을 주장하지 않고 `build/boot.png`를 기존 기록으로 보여준다. 이후 위 소스 범위를 읽으며 예상 흐름을 추적한다. GDB는 1회차 필수 요소가 아니다. 실행 바이너리와 심볼의 일치 검증 없이 소스 중단점 시연을 약속하지 않는다.
