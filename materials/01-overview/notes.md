# 01 강사용 해설: CPU·어셈블리 입문 포함

## 수강생과 목표

CPU 구조, 보호 모드, 어셈블리 선수 지식은 요구하지 않는다. C의 변수·함수·포인터를 본 적이 있다고 가정하지만, CPU 레지스터와 C 변수의 관계는 다시 설명한다. 목표는 명령어·표의 비트 배치 암기가 아니라 **CPU가 무엇을 실행하고 어떤 상태가 바뀌는지 말하는 것**이다.

42장 중 기초 설명에 시간을 우선 배정한다. 이해가 늦어지면 27장의 페이징 명령별 분석과 33장의 iret 프레임 상세를 강사용 참조로 돌리고, 모드 선택지 비교와 전체 부팅 경로는 유지한다. 2회차에서 스택·GDT·IDT를 다시 다루므로 첫날에 모두 숙달시키려 하지 않는다.

## 슬라이드별 해설

| 슬라이드 | 해설과 확인 질문 |
|---|---|
| 01 | 오늘은 CPU 구조를 몰라도 시작한다. “셸이 나오기 전에 누가 실행되는가?”라는 질문을 남긴다. |
| 02 | 16회 지도. 매 장 상단은 오늘 수업의 위치, 이 장의 표는 전체 과정의 위치다. |
| 03 | CPU는 실행, RAM은 실행 중 저장, 디스크는 파일 저장, 장치는 입출력. 캐시·버스 상세는 생략한다. |
| 04 | bit는 0/1, byte는 8 bits. 0x10을 십진수 10으로 읽지 않게 한다. 32비트가 모든 명령의 길이라는 오해를 막는다. |
| 05 | 주소는 위치, 값은 내용. “[0x1000]을 12로 바꾸면 주소도 12가 되는가?”를 묻는다. |
| 06 | EAX 안의 하위 16비트가 AX. EIP/CS는 코드 위치, ESP/SS는 스택 위치. 이 다섯 이름을 본 뒤에만 코드로 이동한다. |
| 07 | 읽기→해석→실행의 단순 모델. jump는 다음 위치를 바꾼다. 현대 CPU의 실제 파이프라인과 동일한 내부 구조라고 설명하지 않는다. |
| 08 | CPU는 C 문자열이 아니라 기계어를 실행한다. .c/.s/.o와 컴파일·어셈블·링크의 의미를 설명한다. |
| 09 | as86는 목적지,원본 / AT&T는 원본,목적지. #와 $는 해당 문법에서 즉시 값을, %는 AT&T 레지스터를 나타낸다. 두 명령은 같은 숫자를 서로 다른 크기의 레지스터에 복사하는 예다. |
| 10 | mov 뒤 EAX=1, add 뒤 EAX=3. 일반적인 mov는 산술 플래그를 바꾸지 않고 add는 바꾼다. 메모리 쓰기는 없다고 짚는다. |
| 11 | pushl은 ESP를 4 줄인 뒤 저장, popl은 읽고 4 증가. call/ret가 복귀 위치를 사용하는 이유를 설명한다. 값이 메모리에서 자동 삭제되지는 않는다. |
| 12 | 사용자 프로그램의 실수가 커널·타 프로그램을 망가뜨리지 않도록 CPU의 검사가 필요하다. 커널도 버그가 있을 수 있다. |
| 13 | 실주소 모드의 세그먼트×16 모델과 보호 모드의 설명표 모델을 대비한다. 실주소 모드를 “아무 한계가 없는 모드”라고 부르지 않는다. |
| 14 | 선택자는 주소 자체가 아니라 설명표 항목을 찾는 값이다. GDT는 전역 세그먼트 설명표, LDT는 태스크별 설명표, IDT는 사건 진입 정보라는 정도만 소개한다. |
| 15 | 선형 주소와 물리 주소를 처음 구분한다. 0x2000→0x9000은 설명용이며 실제 부팅 초기 매핑은 identity mapping이다. 4 KiB 페이지는 7회차에서 확대한다. |
| 16 | 장치 신호, CPU 예외, 프로그램 요청을 구분한다. 시스템 콜도 소프트웨어 인터럽트 명령으로 진입할 수 있으므로 “인터럽트는 모두 장치에서 온다”는 설명을 피한다. |
| 17 | 문맥은 실행 위치·스택·상태다. iret가 모든 범용 레지스터를 자동 복구한다고 말하지 않는다. 첫 사용자 진입도 복원할 프레임을 인위적으로 만들어 구현한다. |
| 18 | PE, PG, IF, CPL을 큰 소리로 풀어 읽는다. 서로 다른 축임을 확인한다. CPU 전체 제어 비트의 목록이 아니라 이번 수업의 참조표다. |
| 19 | 호스트·QEMU·게스트를 구분한다. TCG는 QEMU의 소프트웨어 CPU 실행 방식이며 현대 호스트 커널과 0.11을 혼동하지 않게 한다. |
| 20 | src는 원본, lab은 실행 수정본, build는 수정 기록. 실제 실행과 원본 분석의 차이를 공개한다. |
| 21 | 전체 제어 흐름 지도. 호출 순서와 상태 변화도는 목적이 다르다. |
| 22 | QEMU 부팅과 echo/ls를 짧게 보여준다. TCG·IDE·snapshot 설정을 암기시키지 말고 실행 도구의 설정이라고 설명한다. |
| 23 | legacy BIOS는 커널 이전에 실행되는 펌웨어. 부트 섹터는 작은 시작 코드다. UEFI 일반 강의로 범위를 확장하지 않는다. |
| 24 | bootsect/setup/head의 책임을 나눈다. A20은 주소선 호환 처리, PIC는 장치 인터럽트 제어기라는 용어 풀이만 제공한다. |
| 25 | mov는 준비, lmsw는 제어 비트 설정, jmpi는 CS를 포함한 이동이다. 보호 모드도 16비트 코드를 실행할 수 있다. |
| 26 | 3줄을 각각 읽고 변경된 상태를 묻는다. PE=1 뒤 far jump로 준비된 32비트 코드 항목을 사용한다. |
| 27 | 심화 참조 가능. xorl의 두 피연산자가 같아 EAX=0, CR3=0, orl이 PG 비트를 켠다. 이전에 쌓은 main 주소를 ret가 사용한다. 전체 setup_paging의 테이블 생성은 3회차에서 읽는다. |
| 28 | 단계별 PE/PG/CPL/IF 상태를 소리 내어 비교한다. IF는 표시한 지점의 값이며 전체 부팅 시간 동안의 값을 뜻하지 않는다. |
| 29 | 80386의 real/protected/virtual-8086 선택지를 빠짐없이 소개한다. VM86은 보호 환경의 8086 호환 실행 형태이며 오늘 경로에서 사용하지 않는다. |
| 30 | CPL 0~3 모두 비교한다. 1·2도 존재하지만 0.11의 주 경로는 0/3이다. 사용자 권한은 real mode가 아니다. |
| 31 | PG 0/1, IF 0/1을 각각 읽는다. IF=1이 모든 IRQ의 무조건 전달을 보장하는 것은 아니며 PIC 마스크 등도 영향을 준다. |

| 33 | 심화 참조 가능. 사용자 SS/ESP/CS/EIP와 EFLAGS를 프레임에 준비한다. 동일 task의 권한 변화이지 새 프로세스 생성이 아니다. |
| 34 | 프로그램은 파일, 프로세스는 실행 단위, PID는 식별 번호. fork/exec/wait를 일상어로 먼저 설명한다. |

| 36 | task 0과 PID 1은 별도 흐름이다. init은 rc 자식을 기다린 후 대화형 셸을 생성한다. init 자신은 셸로 교체되지 않는다. |
| 37 | fd는 프로세스의 파일 번호. 0/1/2 관례, open 접근 모드 세 가지를 비교한다. dup는 파일 내용을 복사하는 함수가 아니다. |
| 38 | 코드의 setup은 디스크·루트 준비, open/dup는 tty 연결이다. fd 0부터 할당되는 것은 이 초기 성공 경로의 조건이다. |
| 39 | exec는 같은 PID의 주소 공간과 실행 이미지를 바꾼다. 성공 시 반환하지 않으며 실패하면 이 코드는 _exit로 종료한다. |
| 40 | 내장 명령은 항상 fork/exec하지 않는다. 결과 화면과 소스에서 추론한 내부 동작을 구분한다. |
| 41 | CPU가 실행하는 형식, 두 어셈블리 문법, 보호 모드와 권한 차이, 부모·자식 관계를 확인한다. |
| 42 | 부팅→커널 초기화→init→셸을 학습자의 말로 요약한다. 2회차는 오늘 처음 소개한 구조를 다시 확대한다. |

## 처음 등장하는 용어 풀이

- BIOS: 커널 이전의 PC 펌웨어. 이 프로젝트의 legacy 부팅 경로 기준이다.
- GDT/LDT: 세그먼트 시작·범위·권한 등의 설명을 저장하는 표.
- IDT: 인터럽트·예외 등의 진입 정보를 저장하는 표.
- CPL: 현재 실행 중인 코드의 권한 수준. 낮은 숫자가 높은 권한이다.
- PE/PG: CR0의 보호 환경/페이징 제어 비트.
- IF: EFLAGS의 마스크 가능한 인터럽트 허용 비트. NMI와 예외는 별도다.
- IRQ/PIC: 장치 인터럽트 요청 / 이 요청을 제어하는 장치.
- tty/fd: 터미널 장치 / 프로세스가 열린 파일을 참조하는 번호.
- init: 첫 사용자 프로세스가 수행하는 초기화·자식 관리 흐름. 이 버전은 main.c 안에 구현되어 있다.

## 모드 설명 범위와 정답

CPU 범위는 80386이다. real-address, protected, virtual-8086을 비교하고 실제 경로는 real→protected로 표시한다. 현대 x86-64 long mode/compatibility, SMM은 이 CPU 범위 밖이다. CPL, PG, IF는 CPU 모드와 별개로 설명한다. open 접근 모드는 O_RDONLY/O_WRONLY/O_RDWR 세 가지이며 다른 플래그 전체는 12회차 범위다.

확인 질문 정답: CPU는 기계어 실행 / 주소와 값은 별개 / 두 어셈블리 문법은 피연산자 순서가 반대 / 사용자도 protected에서 실행 / 첫 부모는 task 0의 pause 루프 / init은 자식에서 셸 실행 / exec는 PID 유지 / init이 셸 종료를 회수한다.
